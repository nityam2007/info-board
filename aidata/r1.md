AI-Assisted Information Board – Product Requirements Document
Product Summary and Positioning
The Information Board is a minimalist knowledge capture and retrieval tool. Users are always greeted by a black input screen (the Input Home) with a single content box: whatever text, image, link, audio snippet or clipboard content the user enters becomes an immutable Post (the system never alters the original content). This raw “inbox” approach means all information is captured first, and organization or action is decided later. There are no folders, tags or headers visible at input time. Instead, the system uses invisible facets (by content type, date/time, origin, etc.) and user views (like search or spatial layout) to surface and group posts. Search is front-and-center: as soon as the user types, the same input box doubles as a powerful search bar, reflecting the modern search-first paradigm
. In essence, the product is positioned as a “second brain” vault: a flexible, content-agnostic canvas for ideas and reminders, where AI only suggests metadata (e.g. tags or tasks) but never modifies user content.
Core Use Cases
Capture Anything Anywhere: A user saves a note, image, link, or audio clip instantly via the single input box, with no extra prompts or fields (leaning on the “single entry point” principle
). For example, a user pastes a screenshot into the box and hits Enter: a new Post is created with that image as-is.
Retrospective Organization: Later, the user searches or browses to locate or group items. Because original posts are never edited after creation, actions like setting a reminder or adding a tag create linked references back to the original Post. E.g. a user marks a Post as a task due next week by attaching a “reminder” reference to it, without altering the Post text itself.
Contextual Search and Filtering: The user types a query into the input box to find relevant posts. The interface instantly shows results and contextual filters (facets) on the side – for example, content type, date ranges, or source tags. This “faceted navigation” lets users narrow results by multiple dimensions (just like selecting filters on Amazon)
. No rigid folder hierarchy is needed.
Spatial Brainstorming & Browsing: On the Spatial Board view, posts appear as nodes on an infinite, zoomable canvas. New posts are initially placed by system heuristics (e.g. by timestamp and content similarity), but users can move them freely. Over time the board reveals clusters of related items: a chronological timeline, topical groupings, and frequently accessed content naturally coalesce into spatial patterns
. The user can zoom or pan endlessly to explore older or related posts.
Target Users
The Information Board is aimed at knowledge workers, researchers, writers, and lifelong learners who deal with diverse information flows and prefer capturing everything without immediate categorization. It suits users who want minimal friction for note-taking and idea capture – the kind of people who might use a quick smartphone voice memo or capture screenshots throughout the day. These users value:
Content-Agnostic Capture: They often need to collect mixed media (text snippets, web clippings, images, voice memos) in one place
.
Flexible Organization: They dislike rigid folder structures and instead want multiple, emergent ways to retrieve information later
.
Privacy and Control: They prefer to own their data locally/offline, and trust manual verification over automated AI edits (AI may suggest tags or next steps but never edits their thoughts).
Functional Requirements
Universal Input (Capture): The homepage has a single large input box on a dark background. It must accept multiple content types: plain text (notes, code, quotes), image files, audio clips, URLs, and arbitrary clipboard content. Upon submission, the content is saved immediately as a new Post with a timestamp and source metadata. The system stores the original content exactly; it never overwrites or auto-corrects it (preserving an immutable “single source of truth” for each item).
Post Handling and Metadata:
Each Post has only minimal visible metadata (e.g. date/time, content preview). All editing of a post’s content is disabled by design.
Users can attach tasks, reminders, or tags to a Post. However, these are references to the Post, not changes to its content. For example, turning a Post into a “to-do” creates a separate Task object linked to that Post. If the Post is an image or document, tasks or notes overlay or reference that item but never alter it.
The system may automatically suggest tags or reminders via AI (see AI Assistant below), but the user has to confirm. Suggested tags appear as optional labels (facets) on the post, not as fixed folder paths or bullet points. Users can delete or modify these tags from a tag list view rather than in the input box.
AI Assistant (Secondary):
Tag & Task Suggestions: Optionally, once a post is created the system can run an AI analysis to propose tags (topics, project names, etc.) and action items (e.g. “Turn into task: follow up on…”)
. AI never rewrites the original content; it only adds suggestions that the user can accept or reject. This preserves user trust and content integrity.
Natural-Language Search Enhancements: The search engine supports natural-language queries (e.g. “photos from last week with meeting notes”). The AI may suggest refined queries or autocomplete to help find relevant posts, but only as an aid.
Search Interface: The same central input box doubles as the search bar when not adding content. When a user types a query, the interface switches to a results mode with a faceted sidebar. Search is designed for exploratory use: facets (e.g. Content Type, Date Range, Source App, Manual Tags) appear contextually based on the query
. Users can check or uncheck facet filters in any order (never forced to follow a fixed drill-down path). This faceted navigation ensures users can narrow results multidimensionally rather than relying on folders
. Instant search should be highly performant, with results appearing as the user types.
Spatial Board Behavior: The Spatial Board is an infinite canvas view of all posts. It functions like an on-demand, zero-friction whiteboard for ideas. Key behaviors:
Placement: New posts auto-appear on the board based on a combination of factors: chronological order (e.g. newer items cluster in one region), content similarity (similar topics cluster together), and user engagement (recently viewed items may gravitate nearby). For example, chronological timelines can form naturally as events spread across one axis
.
User Control: Users can drag posts anywhere, creating manual groupings or mind maps. This manual rearrangement helps users “imbue meaning” spatially
. Over time, persistent clusters emerge (e.g. all cooking-related notes end up in one zone).
Zoom & Pan: The canvas is seamlessly zoomable and pannable. Users can zoom out to see global structure (finding broad themes or the “day-by-day” timeline) or zoom in to focus on a cluster. Like a map, the board extends infinitely; there are no fixed edges.
Multimedia Support: Posts on the board can be images, text blocks, or previews of documents and links. Everything is scaled and rendered so that content is readable at different zoom levels.

Non-Functional Requirements
Performance: The app must remain highly responsive. Searches and filter updates should complete in milliseconds even with tens of thousands of posts. Rendering the spatial board should leverage smooth hardware-accelerated zoom/pan (no janky redraws). Indexing for search happens in the background.
Privacy & Data Ownership: All data is stored locally by default. Users’ content is never sold or shared. If cloud sync is offered, it must be opt-in and end-to-end encrypted. The system should follow a “local-first” architecture so users can work offline and trust that their data is theirs (inspired by tools like Obsidian)
.
Transparency: Any use of AI (for tag/task suggestions or query interpretation) must be clearly labeled. Users should be able to toggle AI assistance on or off. The system should log what suggestions it gave and why, so users can audit and learn (avoiding “black box” behavior).
Reliability & Durability: Posts and their metadata (timestamps, links) must be robustly stored (e.g. transactional database or append-only log) so nothing is lost or corrupted. Once a post is created, it cannot be inadvertently overwritten; even deletions should require confirmation (akin to “undoable” logs).
Offline Mode: The core capture and search features should work entirely offline. Users can jot notes or add content without an Internet connection, and sync changes when back online. All searches and AI suggestions (if used offline) should have a local fallback.
Accessibility: The minimal interface with large, high-contrast text on a dark background should meet accessibility standards. Keyboard-only operation should be fully supported (e.g. quick keys to open search, create new task, switch views).
Out-of-Scope Features
Hierarchical Organization: There are no draggable folder trees, no nested notebooks, and no traditional menu-based categories. The system does not support “notebooks” or “projects” in the conventional sense – all structure emerges from tags/facets and spatial arrangement.
Rich Editing: Posts are not meant to be rich-documents. There is no WYSIWYG editing within posts (no formatting toolbars, no embedded spreadsheets, etc.). The focus is raw content. Users cannot, for example, rearrange paragraphs inside a Post – any restructuring would require creating a new Post.
Full AI Authoring: The product explicitly avoids auto-generating or rewriting user content. It does not summarize or paraphrase posts unless the user explicitly invokes a separate “summarize” action; there is no automatic re-writing or “optimizing” of user notes.
Collaborative Multi-User: Initially, the board is personal only. Real-time multi-user collaboration (multiple people editing the same canvas simultaneously) is beyond the first version. Comments and chat are also out of scope.
Complex Permissions/Sharing: While export or sharing options may be considered (see Future), building an enterprise-style permissions system or multi-tenant intranet is not planned in the core product.
Future Possibilities
Enhanced AI Features: Future iterations could let AI synthesize a summary of related posts, or suggest “next steps” for goals found in the content. For example, the AI might propose a task like “Follow up with Alice” if it detects a meeting note in a post – but always requiring user approval.
Collaboration: Allowing multiple users to share a board or subset of posts, with permissions (view/edit) could extend its use to team projects or shared research. Real-time cursors and chat bubbles on the board might then be added.
Integration & Export: Future connectors could pull content from other apps (email, RSS, browsers) directly into the board via an “inbox” API. Export options might include printing a selected region of the board as a PDF, or syncing tasks to calendar apps. Data could be backed up or transferred via standard formats (Markdown, JSON).
Mobile/Desktop Apps: A native mobile or desktop app could improve offline reliability and performance. Mobile notifications could tie into the reminder system. Handwriting or voice-to-text input might be added.
UX Principles and Constraints
Minimal Interface (“No Chrome”): The UI must remain as invisible as possible. Outside of the input/search box, there are no persistent toolbars or icons. The design favors whitespace and simplicity, reducing cognitive load
. By removing extraneous buttons and labels, users focus on content itself, not on the UI
.
Emergent Organization: The system relies on user-driven patterns and flexible labels rather than enforced structure. Tags (or filters) are created fluidly – for instance, typing #meeting in the input might automatically tag the post with “meeting” – but there is no tag-management screen or taxonomy editor. This “network-first” approach mirrors how people naturally think, using associative links over rigid categories
.
Search-Centric Navigation: Consistent with modern UX findings, we assume users prefer typing to clicking through menus
. Thus, every view emphasizes the central search box. Even on the Spatial Board, a keystroke should jump to the search box for filtering, ensuring search is never more than one action away.
Contextual Interactions: Actions like tagging or creating tasks are accessed contextually (e.g. via a right-click or keyboard shortcut on a post), not through a main menu. This keeps the main screen clean. For example, right-clicking a post might reveal only “Add Tag”, “Create Reminder”, or “Link Another Post” – all of which act as overlays rather than taking the user to a different page.
Consistency and Feedback: Despite the minimalism, users need clear feedback. Upon creating a post, the system might show a brief highlighted thumbnail or toast notification. If a user hovers over a post, subtle outlines or shadows indicate clickability. Animations (e.g. posts gently sliding into place on the board) reinforce the spatial metaphor without overwhelming the screen.
No Breadcrumbs or Menus: There are no breadcrumb trails or file menus; the app’s navigation is either via search or via contextual controls. This follows the trend that modern apps use search-first, not breadcrumbs
. Users never “go to” a fixed page other than the Input/Search page or the Spatial Board; everything else is a mode of that main space.
The above specifications outline a product where the user’s raw input always stays intact, while organization arises through intelligent search and visualization. By keeping AI and UI chrome in the background, the board stays personal and flexible – truly becoming an “information-first” workspace rather than an app with a fixed structure
